### 两套登录流程怎样区分

中育的学校发现接口带 `code` 参数，登录条目列出 `AppName`、`AppVersion` 和 JSON 请求体。登录后获取用户信息和刷新令牌是两个独立条目。领创的桌面客户端使用另一个 JSON-RPC 入口。Apifox 没有给出两套会话之间的令牌交换或通用性约定。[导出条目的参数与请求体类型](evidence/apifox.json)

领创的 `InitLoginHelper` 把账号标识、学校、班级、姓名和兴趣班写入初次登记对象。普通登录由 `CommonLoginRequestHelper.onlineLogin` 发起，请求对象同时包含用户输入的账号标识及口令、应用商店版本、桌面版本、ROM 版本、设备序列号和 Android ID。两处客户端代码都先序列化业务对象，再设置外层请求的方法和参数。这里能确定客户端准备哪些信息；服务端究竟按哪些字段验权，仍缺服务端文档或实测。[初次登记对象赋值](../sources/领创平板管理-2025.9.1/java/com/android/launcher3/network/InitLoginHelper.java#L55) · [普通登录对象赋值](../sources/领创平板管理-2025.9.1/java/com/android/launcher3/network/CommonLoginRequestHelper.java#L53)

Apifox 的访问令牌用于读取上述文档。导出期间没有使用教学账号登录，没有调用业务 API。原厂身份校验及服务器端实现不随 APK 提供。目录保留路径、字段名称及声明类型。文档示例的字段值和实际会话凭据均未写入目录。

### 登录文档具体声明了哪些字段

中育登录的两个查询参数是 `AppName` 和 `AppVersion`。请求体声明 `userName`、`password` 两个字符串。`200` 响应的类型定义将 `accessToken` 和 `refreshToken` 声明为字符串，`expireInSeconds` 和 `refreshExpireInSeconds` 声明为整数。它还列出了用户 ID、角色、是否需要改密和是否需要短信验证等字段。文档没有给出可据此确认的实际有效期。[认证条目及解析后的类型](evidence/apifox-operations.json)

领创统一 JSON-RPC 入口声明 JSON 请求体与 JSON 成功响应，两者在结构定义中均为空对象模型。学校发现、获取用户信息和刷新令牌的成功响应也使用空对象模型。开发时可以从导出文件确定它们的 HTTP 签名，更具体的领创回调由下面的 Android 实测补足。[只读导出的目录生成程序](../tools/verification/apifox_catalog.py)

在离线模拟器上共同安装配套应用后，九个教学应用启动到 UnLoginActivity。本次启动检查在前台读到中育管控桌面的 MainActivity 和领创平板管理的 LauncherNew，均未进行设备登记或账号登录。文档访问、客户端会话分发和服务端认证属于三处独立证据。[模拟器启动记录](evidence/emulator-compat.json) · [首次登录客户端代码](../sources/领创平板管理-2025.9.1/java/com/android/launcher3/network/InitLoginHelper.java) · [普通登录客户端代码](../sources/领创平板管理-2025.9.1/java/com/android/launcher3/network/CommonLoginRequestHelper.java)


### 原包如何处理业务响应

普通登录的成功回调以 UserInfo 作为期望类型，随后读取用户 ID、账号标识及学校信息。业务失败和传输失败分别进入 onFailed 和 onFailureByNet。领创的 LTKResponseListener 在解码后的 JSON 中检查 code。code 为 0 时根据 type 读取布尔、字符串或对象，对象再交给指定模型；列表监听器单独处理数组。业务错误的 code 和 data 会进入失败回调。此处的 code 属于客户端解析的业务信封。[普通登录回调](../sources/领创平板管理-2025.9.1/java/com/android/launcher3/network/CommonLoginRequestHelper.java#L72) · [REA 原方法](evidence/linspirer/rea-response.json)

Android 实测在内存中把九组合成输入交给原 APK 的响应解析器。它分别返回带学校名的示例用户、布尔 false、字符串、有序的两个用户和空列表。测试业务错误保留了自定义错误码和说明；成功信封缺少 type、列表 data 类型错误均返回本地错误码 −200。传输异常进入独立回调。本次验证覆盖客户端回调分派，线上学校的账号许可、会话到期和设备绑定仍需在相应服务环境下核对。[九项原包回调结果](evidence/linspirer/response-parser.json) · [验证入口](../tools/verification/verify_linspirer_response.py)
